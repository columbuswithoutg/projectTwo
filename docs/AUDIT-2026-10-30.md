### CLI2-03 — A visitor with an expired token in localStorage is sent to /login when they open a public share link
- category: bug
- where: js/messages.js:52-58 (MessagesBadge.refresh → Auth.endSession), js/friend-view.js:88 (`state.ensureLoaded()`), js/state.js:67-71, js/auth.js:354-363
- likelihood: Medium
- confidence: High (reproduced in a vm harness: Router.go('/login?next=%2Fs%2FabcDEF123_-x') and enterShared never settles)
- new-since-audit: yes
- what happens: Someone who used the app in this browser more than 7 days ago taps a friend's /s/<token> link (from WhatsApp or iMessage, so it opens in the default browser). SharedView.topbar() calls Auth.isLoggedIn(), which drops the stale token and sets `_expired`. boot.js then calls MessagesBadge.start() → refresh(). That sees `sessionExpired()` and calls Auth.endSession(), which runs logout({ next: '/s/<token>' }) → /login. On its own path, FriendView.enterShared → state.ensureLoaded → load() also takes the "expired" branch → Auth.fetch → endSession: the same redirect, and enterShared hangs for good. The public page, which needs no account, is replaced by a login form. A token that is still valid but revoked does the same through the 401.
- fix: On a public route (Router._debug.isPublic(location.pathname)), have MessagesBadge.refresh clear the expired flag and apply(0) instead of ending the session. Have FriendView._enterWith await ensureLoaded only when Auth.isLoggedIn(). Add a test next to test/friend-view-restore.test.js for "expired token + /s/ path → no redirect, enterShared resolves". Files: js/messages.js, js/friend-view.js, test/friend-view-restore.test.js (or test/share.test.js).

- confidence: High
